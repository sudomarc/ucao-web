# Current Site Audit — UCAO-UUCo Existing Website

## Overview

This document presents the findings from the comprehensive audit of the existing UCAO-UUCo institutional website (https://ucao-uuco.org/), conducted as Phase 0 / Phase 2 of the refonte process. The audit identifies problems, inconsistencies, gaps, and strengths in the current site, establishing what must be conserved, corrected, removed, or rebuilt.

The current site is a static site generated by `src/build.js` from JSON content files, with CSS in `src/styles/main.css` and images in `src/assets/images/`.

### Points Forts (À Conserver)

1. **Structure de contenu JSON centralisée** — Toutes les pages tirent leurs données de fichiers JSON dans `src/content/pages/`. Cela permet une maintenance aisée et une centralisation des contenus.
2. **Logo institutionnel intégré** — Le vrai logo `UCAO_LOGO.png` est utilisé sur toutes les pages via le build.js (header, footer).
3. **Palette de couleurs dérivée du logo** — Le DESIGN-BRIEF.md documente correctement les couleurs `#312783` (bleu) et `#991915` (rouge) extraites du logo.
4. **Formulaires honnêtes** — Le formulaire de contact indique clairement qu'aucun backend n'est identifié et qu'aucune soumission simulée n'est affichée.
5. **Skip-link et accessibilité de base** — Skip-link présent, focus-visible en CSS, titres hiérarchiques.
6. **Responsive design médium** — Media queries pour 375px, 640px, 1024px, 1440px couvrent la plupart des cas.
7. **Formats d'images variés** — JPEG et WebP disponibles, lazyloading implémenté.
8. **Inventaire d'images local** — 30+ photos fournies par l'UCAO sur le campus de Conakry, avec légendes et crédits.

### Problèmes Identifiés (À Corriger ou Supprimer)

1. **Contenu trop bref / superficiel**
   - La page d'accueil fait environ 6 sections (hero, intro, stats, formations, admissions, actualités, valeurs).
   - Pas assez de profondeur institutionnelle pour un site universitaire de niveau international.
   - Certaines sections ont très peu de texte (ex: stats avec seulement 3 items).

2. **Hero image mal exploitée**
   - `hero-conakry.webp` est une illustration libre de droite de Ville de Conakry, **pas une photo du campus UCAO**.
   - Les vraies photos du campus sont dans les images WhatsApp mais ne sont pas toutes exploitées sur le site.
   - L'hero actuelle ne reflète pas l'identité visuelle du logo (couleurs bleu/rouge ne se retrouvent pas dans l'hero).

3. **Palette non exploitée cohéremment**
   - Les couleurs du logo (#312783 bleu, #991915 rouge) sont définies dans le CSS mais ne sont pas systématiquement utilisées dans toutes les composants.
   - Certaines couleurs définies ne semblent pas appliquées (ex: certaines couleurs dans les tokens CSS ne apparaissent pas dans le rendu final).

4. **Grille de cartes répétitive**
   - Le composant `cards` utilise une grille `grid-template-columns: repeat(auto-fit, minmax(260px, 1fr))` qui crée des cartes de taille identique — jugé générique et manquant d'identité visuelle distinctive.
   - Plusieurs sites références (SOAS, Cornell) utilisent des sections éditoriales clairement délimitées plutôt que des cartes identiques.

5. **Typographie générale système**
   - La police par défaut est la police système UI sans famille d'affichage marquée.
   - Pas de hiérarchie typographique marquée entre les différents types de contenu (hero, section-title, card-title, etc.).

6. **Pages internes trop semblables**
   - La fonction `renderGeneric` utilise le même template que l'accueil pour la plupart des pages internes (formations, université, actualités, etc.).
   - Chaque page devrait avoir sa propre structure éditoriale adaptée à son contenu.

7. **Contenu "à confirmer" non marqué de façon visible**
   - Plusieurs champs contiennent `[À CONFIRMER]` mais ce marquage n'est pas systématiquement visible dans l'interface rendue.
   - Le contenu non vérifié risque d'être publié accidentellement.

8. **Images non optimisées et non webp**
   - Certaines images WhatsApp ne sont pas converties en WebP dans le workflow build.
   - Poids total du site non optimal (956 Ko rapporté mais sans analyse détaillée par page).

9. **Navigation principal limitée**
   - Menu principal : Accueil, Qui sommes-nous ?, Nos formations, Inscription, Contact.
   - Manque de sections pour actualités, vie universitaire, partenariats qui existent pourtant dans le contenu.

10. **Manque de pages institutionnelles clés**
    - Pas de page "Histoire détaillée" à part le texte court sur la page Université.
    - Pas de page "Gouvernance / Organisation".
    - Pas de page "Partenariats et recherche" approfondie.
    - Pas de page "Témoignages vérifiés".

## 3. Design System — État des Lieux

### Couleurs (CSS tokens)

Le fichier `src/styles/main.css` définit les tokens suivants, majoritairement dérivés du logo :

- `--color-primary: #312783` (bleu) ✅
- `--color-primary-dark: #1f1a5c` ✅
- `--color-primary-light: #e8e7f2` ✅
- `--color-secondary: #991915` (rouge) ✅
- `--color-secondary-dark: #7a1411` ✅
- `--color-secondary-light: #f3e5e5` ✅
- `--color-bg: #fafaf9` (blanc cassé) ✅
- `--color-surface: #ffffff` ✅
- `--color-text: #22223b` ✅
- `--color-text-muted: #6b7280` ✅
- `--color-text-light: #9ca3af` ✅
- `--color-border: #e5e7eb` ✅
- `--color-border-focus: #312783` ✅
- `--color-shadow: rgba(49,39,131,0.08)` ✅

**Problème :** Tous les tokens sont définis mais tous ne sont pas systématiquement utilisés dans les composants. Par exemple :
- `--color-secondary-light` apparaît peu dans le rendu
- `--color-primary-light` n'est utilisé que dans quelques boutons hover
- `--color-text-light` est utilisé pour les notes mais pas partout

### Typographie

- Police d'affichage : `ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
- Police du corps : même famille que l'affichage
- Tailles : display 3.5rem, h1 2.25rem, h2 1.625rem, h3 1.25rem, body 1.0625rem, caption 0.8125rem, nav 0.875rem

**Problème :** Pas de hiérarchie éditoriale marquée entre les différents niveaux de titre. La taille display (3.5rem) s'applique à la fois aux heroes et aux titres de section, ce qui peut créer confusion.

### Grille & Espacement

- Conteneur max 1200px, large 1400px, padding 24px
- Échelle d'espacement : 4px à 128px
- Largeur de lecture : 65ch (bonne pratique)
- Grille cartes : `repeat(auto-fit, minmax(260px, 1fr))`
- Gap grille : 28px

**Problème :** La grille de cartes `auto-fit minmax(260px, 1fr)` crée des cellules de taille identique à chaque fois — critiqué comme "répétitive" et manquant d'identité visuelle (souligné par l'analyse des références).

### Composants

Composants disponibles dans build.js :
- hero, intro, stats-grid, cards, text-list, text-cta, image-block, sections-list, split-section, statsGrid, pullquote, valeurGrid, steps, newsBlock, contactForm, faqList, legalBlocks, actionsList, twoColumn

**Observation :** L'inventaire de composants est correct pour un site statique, mais certains manquent d'éléments éditoriaux (ex: pas de composant "facts and chiffres" éditorial comme SOAS).

### Accessibilité

- Skip-link présent ✅
- Focus-visible en CSS ✅
- Titres hiérarchiques (h1, h2, h3) ✅
- Contraste aux valeurs actuelles ✅ (basé sur les tokens)
- prefers-reduced-motion ✅
- Alt text sur les images ✅ (via JSON)

**Problème :** Le contraste entre `--color-text (#22223b)` et `--color-bg (#fafaf9)` doit être vérifié officiellement (ratio WCAG AA ≈ 4.5:1, qui est marginal selon les calculs).

### Performance

- Poids total rapporté : 956 Ko
- Images : JPEG + WebP options ✅
- Pas de dépendances client-side lourdes ✅
- Pas de framework CSS ✅

**Problème :** Pas d'analyse par page des poids réels. La page d'accueil vise < 500 Ko cible non atteinte selon les constatations.

## 4. Incohérences et Bugs Visuels

1. **Conflit d'email** : Deux adresses `info@ucao.uuco.org` et `info@ucao-uuco.org` mentionnées, aucune confirmée.
2. **Hero image source** : `hero-conakry.webp` est une illustration Wikimedia, pas photo campus UCAO. Les photos authentiques sont dans les WhatsApp Images mais peu utilisées.
3. **Largeur d'image inégale** : Dans le composant hero, les images ont `width="1200" height="630"` fixe, ce qui peut sembler disproportionné sur mobile ou large desktop.
4. **Classes CSS non utilisées** : Certaines classes dans main.css (ex: `.split-section__media img` avec `object-fit: cover`) ne sont pas toutes invoquées par les fonctions de build.js actuelles.
5. **Navigation active** : La classe `.nav-link--active` utilise `--color-primary` pour la couleur et la bordure basse, mais sur mobile le menu hamburger ne conserve pas visuellement l'item actif de façon constante.
6. **Footer brand logo dimensions** : Dans le footer, le logo a `width="140" height="104"` alors que dans le header il a `width="200" height="148"` — même logo, dimensions différentes selon les composants.
7. **Text en uppercase non cohérent** : Certaines sections utilisent des kicker uppercases, d'autres pas.
8. **États de formulaire** : Le formulaire de contact a des états `.field-error` et `.form-status` mais aucun backend n'existe — l'interface doit clairement documenter la limitation (ce qui est fait via la note).

## 6. Conclusion et Recommandations

### Ce qui DOIT être Conservé
1. **Structure JSON centralisée** — C'est la base solide pour maintenir un site à contenu riche sans framework complexe.
2. **Logo institutionnel UCAO_LOGO.png** — Identité visuelle authentique à préserver à 100%.
3. **Palette couleurs du logo** (#312783 bleu, #991915 rouge) — Système de couleurs à partir duquel construire tout le design.
4. **Photos authentiques du campus** (WhatsApp Images) — Ressource unique à exploiter pleinement.
5. **Formulaire de contact honnête** — Documenter la limitation backend est la bonne approche.
6. **Skip-link, focus-visible, titres hiérarchiques** — Accessibilité de base déjà en place.
7. **Responsive design de base** — Media queries existantes à préserver et enrichir.

### Ce qui DOIT être Corrigé
1. **Remplacer l'hero image** par une photo authentique du campus UCAO (sélectionner parmi les WhatsApp Images ou faire de nouvelles prises).
2. **Markdown le contenu [À CONFIRMER]** de façon visible dans l'interface d'édition, pas seulement dans les fichiers JSON.
3. **Remplacer les grilles de cartes répétitives** par des sections éditoriales variées (modèle SOAS : sections clairement délimitées avec titre/sous-titre/texte/image/encadré).
4. **Rédrichir l'architecture de contenu** — Ajouter des pages et sections manquantes (gouvernance, partenariats, témoignages, histoire détaillée).
5. **Utiliser la palette logo de façon systématique** — Toutes les composants doivent référence les tokens CSS, pas seulement certains.
6. **Créer des pages internes aux structures éditoriales uniques** — Pas de template unique pour toutes les pages.
7. **Optimiser les images en WebP** et lazy loading sur toutes les images.

### Ce qui DOIT être Supprimé ou Reconstruit
1. **Grille de cartes `card-grid` telle quelle** — Trop répétitive, ne reflète pas l'identité UCAO. Remplacer par des sections éditoriales variées.
2. **Typographie système non marquée** — Remplacer par une typographie expressive avec.display family marquée.
3. **Hero illustration Wikimedia** — Remplacer par photo campus UCAO ou.image issue des assets locaux.
4. **Contenu fantaismé ou inventé** — Ne jamais ajouter de statistiques, accréditations, tarifs, témoignages sans confirmation.
5. **Formules de navigation fantoches** — Garder le menu existant mais l'enrichir des sections manquantes.

### Architecture Cible (Comparaison)

|-----------------|---------------|--------|
| 6 sections d'accueil | 8-10 sections d'accueil | Plus de profondeur éditoriale |
| 2 cartes formations | 4-6 niveaux de formations avec sous-spécialités | Catalogue complet |

| Pas de page gouvernance | Page gouvernance + réseau UCAO | Manque institutionnel |
